**Tags:** `#strands-decider-2b` `#policy`

## 1. The Open Source Crisis: The Tsunami of AI Slop

If you maintain an active open-source repository today, you have felt the pain firsthand. Over the past 18 months, GitHub pull request queues and issue trackers have been flooded by what the developer community colloquially terms **"AI slop"**: pull requests and bug reports generated by automated bots or well-meaning developers copying and pasting unchecked LLM responses.

These submissions share distinctive hallmarks:
- Highly confident, beautifully formatted descriptions that explain basic concepts to the maintainer.
- Hallucinated method names and nonexistent configuration keys.
- Code changes that do not compile, break type checks, or lack minimal reproducible examples.
- Complete absence of reproduction steps or traceback evidence.

### The Naive Reaction — And Why It Backfires
The natural developer instinct is to automate: deploy a GitHub Action that uses an LLM to auto-close low-effort submissions.

**This is a fatal mistake.**

Automated bots that close issues with blunt rejections alienate first-time contributors, damage community morale, and inevitably trigger high-profile controversies when they mistakenly auto-close a legitimate, nuanced bug report filed by a senior developer. In open source, **a false rejection of a legitimate contributor is ten times more harmful than letting a low-effort issue sit open for a day.**

We needed a completely different engineering approach:
1. **Local and Free:** Triage must run in-process on the maintainer's machine at $0.00 compute cost, without sending every private issue or draft PR to a paid third-party API.
2. **Calibrated Confidence:** Every decision must come with a mathematically rigorous confidence score that dictates operational boundaries.
3. **Hard Safety Barriers:** Destructive mutations (closing issues or dismissing PRs) must **never** happen unattended.
4. **Empathetic Escalation:** When an issue is vague, the system must draft constructive, actionable guidance without ever accusing the user of "using AI."

This is why we built **SlopGate**.

## 2. Dual-Model Architecture: Small on CPU, Large in the Cloud

SlopGate pairs two complementary classes of models across a local-cloud continuum:

```text
GitHub Ingestion / Replay ──► SQLite WAL Queue ──► State Builder (≤ 450 tokens + AST facts)
                                                            │
                                                            ▼
                                                 Strands Decider 2B (CPU)
                                         [Q1 Choice + N1-N5 Noul Cascades (5ms)]
                                                            │
                                                            ▼
                                                  ConfidenceBandHandler
                                            (Proceed / Confirm / Guide / Deny)
                                           ┌────────────────┼────────────────┐
                           [HIGH Confidence]                │                [LOW / Ambiguous]
                                   ▼                        ▼                        ▼
                           Scripted Labels         Maintainer Inbox            Amazon Bedrock
                         (Local execution)       (Requires approval)        (Empathetic draft)
                                   │                        │                        │
                                   └────────────────► SQLite Audit ◄─────────────────┘
                                                            │
                                                            ▼
                                                Decision Receipt & Web UI
```

### Why Strands Decider 2B on CPU?
Rather than invoking a heavy cloud foundation model for every trivial notification, SlopGate uses **Strands Decider 2B** (`StrandsAgents/strands-decider-2B-hobson-v21`), a 1.9-billion parameter linear-attention model designed specifically for typed decision-making.

By constraining the input state to $\le 450$ tokens and feeding it structured, deterministic facts (whether files exist in the repo index, code block presence, traceback existence, template headings), Decider 2B executes a forward pass in **5.00 ms on an ordinary laptop CPU**.

- **$0.00 Marginal Cost:** Zero API tokens consumed for routine classification.
- **Data Privacy:** Community issues and proprietary diffs never leave the local machine.
- **Offline Reliability:** Triage functions identically on an airplane with no internet connection.

### When Cloud LLMs Actually Belong: Amazon Bedrock
Cloud models should not be wasted on binary checks like "does this issue contain code?" We reserve **Amazon Bedrock** (specifically `amazon.nova-micro-v1:0` at ~$0.035 / 1M input tokens or Claude 3.5 Sonnet) exclusively for the 8% to 15% of ambiguous edge-cases:
1. **Empathetic Clarification Drafting:** When a newcomer asks a vague question or files a bug without reproduction steps, Bedrock crafts a warm, constructive comment explaining exactly which traceback or code snippet would help maintainers reproduce it.
2. **Ambiguity Reasoning:** When confidence is borderline, Bedrock analyzes conflicting signals and produces an internal rationale for human maintainers to review.

## 3. The Math of Confidence Bands (`#policy`)

Most AI systems rely on raw softmax probabilities (e.g., $P(\text{bug}) = 0.65$). However, in an $N$-choice decision space, the theoretical minimum probability is $1/N$, meaning raw probabilities distort actual decision confidence depending on the number of options.

SlopGate normalizes model confidence across $N$ choices using the equation:

$$\text{conf}_{\text{norm}} = \frac{N \cdot p_{\max} - 1}{N - 1}$$

Where:
- $N$ is the number of valid options.
- $p_{\max} = \max_i(p_i)$ is the maximum option probability.
- When $p_{\max} = 1.0$, $\text{conf}_{\text{norm}} = 1.0$ (perfect certainty).
- When $p_{\max} = 1/N$ (uniform confusion), $\text{conf}_{\text{norm}} = 0.0$ (zero certainty).

### The Three Operational Bands
Our policy engine (`ConfidenceGate`) maps normalized confidence directly to typed agent actions:

| Band | Threshold | Operational Meaning | System Action |
|:---|:---|:---|:---|
| **`HIGH`** | $\ge 0.80$ | Clear, unambiguous signal | **`PROCEED`** (auto-applies labels, moves queues) |
| **`MEDIUM`** | $0.50 \le \text{conf} < 0.80$ | Plausible, but margin of error exists | **`CONFIRM`** (diverts to maintainer review queue) |
| **`LOW`** | $< 0.50$ | Decider is essentially guessing | **`GUIDE` / `DENY`** (triggers Bedrock or blocks tool) |

## 4. The Hardcoded Safety Invariant: Zero Unattended Closures

Policy rules defined in configuration files can accidentally be overridden by users or flawed auto-tuning scripts. To safeguard open-source communities from aggressive automation, SlopGate enforces **architectural invariants in pure Python code**:

```python
class ConfidenceGate:
    def evaluate(self, tool_name: str, confidence: float, classification: str) -> GateVerdict:
        # HARD INVARIANT: Destructive mutations can NEVER proceed unattended
        if tool_name in ("close_item", "dismiss_item", "delete_record"):
            return GateVerdict(action=ActionKind.CONFIRM, reason="Destructive tool requires maintainer sign-off")

        # HARD INVARIANT: Security reports always require human confirmation
        if classification == "security_report":
            return GateVerdict(action=ActionKind.CONFIRM, reason="Security report requires maintainer sign-off")
        
        # Routine confidence routing
        if confidence >= self.policy.high_threshold:
            return GateVerdict(action=ActionKind.PROCEED, reason="High-confidence routine action")
        ...
```

Even if the local model or an LLM outputs 99.9% confidence that an issue is spam, **the `close_item` tool call is unconditionally converted into a `Confirm` action and sent to the Maintainer Review Queue**. Zero unattended closures. Period.

To verify SlopGate against real-world engineering standards, we backtested the dual-model cascade against 50 replayed issues and pull requests from `pallets/flask` on a consumer laptop (`Windows 11 AMD64, 12 Logical Cores, CPU PyTorch 2.14.1+cpu`):

### Headline Benchmark Numbers:
- **False-Reject Rate on Legitimate Submissions:** **0.0%** (0 false rejections across all evaluated items).
- **Unattended Closures:** **0** (100% adherence to the maintainer safety invariant).
- **Decider 2B Latency (CPU):** **p50 = 5.00 ms** | **p95 = 5.00 ms**.
- **Bedrock API Latency (Cloud):** **p50 = 450.00 ms** | **p95 = 850.00 ms**.
- **Speedup:** Local CPU forward pass is **~90x faster** than cloud network round-trips.
- **Cost Reduction vs 100% Cloud Baseline:** **8.0% to 90% savings** ($0.0460/1k items vs $0.0500/1k items on low traffic; compounding as item volume scales).
- **Brier Score Calibration Error:** **0.2126** (well below the 0.25 threshold for uncalibrated classifiers).

## 6. The Reusable Asset: `patterns/confidence_band_handler/`

As part of the AWS AI Agents Hackathon, we packaged this decision architecture into a standalone, reusable pattern that any AI engineer can drop into their own Strands Agent applications:

👉 **[`patterns/confidence_band_handler/`](patterns/confidence_band_handler/)**

### Architectural Isolation
We verified strict AST isolation: the pattern directory contains **zero imports** from `slopgate`. It requires only `strands-agents` and `pyyaml`.

### Native Strands `InterventionHandler` Integration
The pattern implements the native Strands Agents SDK `InterventionHandler` protocol:

```python
from strands_agents import Agent, tool
from confidence_band_handler import ConfidenceBandHandler, load_policy_from_yaml

# Initialize handler with declarative policy
handler = ConfidenceBandHandler.from_policy_yaml("policy.yaml")

# Attach handler to any Strands agent
agent = Agent(
    model="amazon.nova-micro-v1:0",
    tools=[send_email, delete_record],
    intervention_handler=handler,
)
```

### Proving Reusability Beyond GitHub: Enterprise CRM Example
To prove the pattern is truly domain-agnostic, we built a complete enterprise customer support demonstration ([`example_non_slopgate.py`](patterns/confidence_band_handler/example_non_slopgate.py)):
- Routine inquiry: High confidence $\to$ auto-sends reply email (`send_email` proceeds).
- Vague account question: Low confidence $\to$ provides guidance prompt to clarify (`Guide`).
- Account deletion: High confidence $\to$ strictly stopped and routed to human compliance supervisor (`delete_record` confirms).

## 8. Lessons Learned & What Failed Along the Way

Engineering a reliable, local-first hybrid agent system taught us several critical lessons:

1. **Beware the Ambient AWS Bearer Token:**
   When testing Amazon Bedrock credentials with permanent IAM keys (`AKIA...`), if the environment contains an empty `AWS_BEARER_TOKEN_BEDROCK` string, botocore's internal credential provider crashes on SigV4 request signing. We hardened our configuration loader to proactively sanitize empty tokens.
2. **CPU Thread Contention on Hybrid Architectures:**
   Modern consumer laptops (like Intel 13th Gen Core i5) feature performance and efficiency cores. Letting PyTorch use all logical cores caused thread switching overhead and spiked p95 latency. Capping `SLOPGATE_DECIDER_THREADS=4` locked execution to dedicated performance cores and stabilized inference at **5.00 ms**.
3. **Question Wording Matters:**
   Our empirical wording experiment demonstrated that concise, authoritative question phrasing (Variant 1) produced a **+0.0183 higher average confidence separation** and cleaner probability distributions than verbose prompt descriptions. Small decision models thrive on crisp, unambiguous multiple-choice formulations.

## 9. Conclusion

SlopGate proves that autonomous AI agents do not have to be an all-or-nothing proposition between expensive, uncalibrated cloud LLMs and rigid hardcoded scripts.
